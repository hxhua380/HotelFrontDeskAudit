# Demo Hotel 模拟数据说明

本数据集完全虚构，供酒店前台订单与录音核对演示使用，不包含真实客人或酒店业务数据。所有记录来自同一家虚构酒店 **Demo Hotel**，音频为 AI 合成语音。不能将其当作真实通话或真人录音。

## 文件边界

| 文件 | 作用 |
| --- | --- |
| `data/orders.json` | 生产演示输入：八个冻结字段的订单；外层标明合成来源、酒店和时区。 |
| `data/tts-manifest.json` | 生成输入：每段录音的时间、路径、独立台词及语音设置。没有预期状态或订单与录音的对应表。 |
| `data/recordings.json` | 生产演示输入：录音编号、开始时间、相对音频路径和实际对齐转写。 |
| `data/audio-metadata.json` | 兼容元数据：生成工具版本、声音、时长、大小、哈希、解码测量和对齐来源。 |
| `audio/*.mp3` | 真正生成的中文语音，可用支持 MP3 的播放器播放。 |
| `audio/*.boundaries.json` / `audio/*.srt` | 服务原始边界及转换字幕，便于审核时间来源。 |
| `tests/fixtures/expected_results.json` | 独立人工标准答案，仅由测试读取；不是生产输入，也不是算法训练标签。 |

订单和录音编号只作为记录标识。相同数字后缀、数组位置或时间先后都不是匹配规则。`src/domain/`、`src/data/` 和 `src/agent/` 不得加载答案文件；数据生成脚本和数据校验命令也不读取它。

## 日期与金额

事件统一使用 `Asia/Shanghai`，办理和录音时刻均显式带 `+08:00`。查询订单时使用办理日；查询录音时使用录音开始日。入住日和退房日单独保存，可能晚于办理日。例如第二天办理的预订安排在 10 月 18 日入住，用于检查日期概念是否混用。

主日期为 2026-10-15，另有 2026-10-16 的订单和录音。语音中没有念出年份的月份/日，应结合录制时刻的 2026 年场景解释；这属于演示的上下文约定，不应扩展成对任意真实录音的假设。

金额始终使用 CNY 整数分。语音中的“元”为人民币元，转成分后才能与订单比较。语音采用中文逐位房号，不能只依靠阿拉伯数字搜索完成字段识别。

## 语音与时间戳来源

使用 [edge-tts](https://github.com/rany2/edge-tts) 调用 Microsoft Edge 的在线语音合成服务。隔离依赖固定在 `scripts/requirements-audio.txt`，语音为普通话 `zh-CN-XiaoxiaoNeural`。具体语速及实际生成版本以 manifest 和 audio-metadata 为准。生成过程不需要 DeepSeek 密钥。

转写以输入台词和服务返回的 `SentenceBoundary` 对齐。原始时间使用服务的 100ns tick 表示，起点向下取整、终点向上取整为相对音频开头的整数毫秒。字幕和 `transcript_segments` 必须能回溯到同一原始边界。

**100ns 是时间字段的表示分辨率，不代表声学对齐精度。** 本数据是服务估计的句子级对齐，适合定位句子，不承诺逐字或逐音素的精确位置。标点可按源台词恢复，但不得补写语音中没有的业务字段。当前流程不使用语音识别，也不把输入文本宣称为独立 ASR 识别结果。

质量检查对真实 MP3 解码后测量时长、采样点、幅度变化及非静音特征，结合原始 TTS 边界校验每段转写。它能排除空文件、伪 MP3、静音和越界时间，但不能替代真人逐句听校。

## 场景与标准答案

八条订单和八段录音不构成八个一一对应的关系。有正常一致、金额冲突、缺少录音、孤立录音、信息不足、一段录音对应多个候选订单，以及同一订单存在多个候选录音。

标准答案按场景分组；无确定对应记录时使用 `null`，并在候选集合中完整列出可能性。`needs_review` 不等于字段冲突：缺少信息和多个合理候选都不能通过臆造证据解决。每条有录音的预期结果引用实际转写片段及相对时间范围，缺失录音案例如实保留空证据。

数据生成流程只准备样本，不实现匹配或状态推断。现有核对算法使用业务字段、时间邻近性和原文证据评估候选，保留不能确定的结果，详见[核对规则](audit-rules.md)。

## 重复生成与失败处理

先运行 TypeScript 数据脚本生成订单和台词清单，再运行 Python 语音脚本。后者先在仓库缓存区合成并检查完整批次，预检发布路径并备份已有文件，通过后才发布目标文件；普通发布错误触发回滚，任一音频失败都应非零退出，不能打印整批成功。已存在且原始边界来源、字幕、哈希和实际解码检查一致的音频可复用，避免无意义地重复请求服务。

脚本只管理自己声明的文件，不删除 audio 或 data 下其他内容。修改台词后必须重新生成对应语音和对齐信息，并重新运行数据质量检查；不要手工编造片段时间。来源与解码信息保存在 `data/audio-metadata.json`，完整项目使用 `npm.cmd run validate:data` 复核。已有 MP3 可直接使用，无需重新生成数据或语音。
