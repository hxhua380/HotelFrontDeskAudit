# 本地网页接口与使用说明

页面采用主从核对工作台与独立 AI 报告。

页面使用 HTML、CSS 和原生 JavaScript；服务端沿用 Express 与现有 Pi runner。正式业务结果来自真实 Agent 成功调用的 audit_day，网页不会从模型文字反推或覆盖结构化结果，不读取人工标准答案。

## 数据来源与启动

本项目使用 Demo Hotel 的虚构订单及 AI 合成中文录音，不是真实客人或酒店通话。页面顶部装饰性演示提示已按需求移除，原始订单、音频、转写中的酒店名称保持原样。README 和此文档保留数据来源与限制说明。

~~~powershell
npm.cmd ci
npm.cmd run dev
~~~

默认绑定 127.0.0.1:3000，可通过服务端 PORT 设置端口。端口占用时选择其他空闲端口。凭据只放服务端环境，不能写入前端、浏览器问题或提交 Git。

## HTTP 契约与证据

| 接口 | 行为 |
| --- | --- |
| GET /api/health | 只反映 HTTP 存活，不证明 Pi 在线；页面继续探测，但不展示开发状态标签 |
| POST /api/audit | 接收 date、question，调用原 runAuditAgent，返回原 status/runId/date/results/warnings/finalAnswer/error? |
| GET /audio/:recordingId.mp3 | 已知合法录音的真实 MP3，支持 Range；目录、路径与 realpath 边界检查沿用原实现 |
| GET /、/style.css、/app.js | 仅公开 public/ 静态资源；配置、业务原始文件和运行日志不作为静态资源公开 |

问题去空格后 1–1000 字；日期必须真实存在。问题明确指定的日期与选择器冲突时拒绝，不以服务器当天替代办理日。HTTP 状态仍为 200/PASS、400/FAIL、503/BLOCKED、502/FAIL、500/FAIL；这些契约未因页面文案精简而变化。

只有本轮真实 runner 成功、工具参数与结果日期一致的 audit_day capture 能构成成功响应。同日结果矛盾时拒绝任取，失败不会返回部分结果冒充成功。runId、toolCallId、Runtime/execute 日志与历史证据均完整保留，普通页面只是不展示运行 ID。

## 页面布局和查询

页面为米白背景、深绿主色和简洁卡片。顶部保留系统名“Hotel Front Desk Audit”与“前台订单与接待录音智能核对”；不显示 Demo Hotel 装饰标签、合成演示框、HTTP/Pi 开发标签和固定技术免责声明。统计下方为“核对工作台”和“AI核对报告”两个标签；桌面工作台采用38/62记录列表/详情，报告在独立全宽内容区阅读，正文最大840px。窄屏工作台单栏，先列表后详情。

日期、问题和开始核对按钮对齐；保留三个示例问题。正常状态为“正在核对订单与录音，请稍候。”和“核对完成”。已知的服务端配置/工具技术错误只在视图层精确映射为业务可理解的原因；其他真实错误保持，不把失败隐藏或写为成功。

编辑问题会清除过期结果，需提交后重查；已查询后切换日期自动只查一次。序列号、输入签名、AbortController 和响应日期检查沿用原机制，避免旧响应覆盖当前结果。加载时阻止重复提交。客户端取消不保证马上终止服务端模型会话，原 runner 仍受 60 秒超时控制。

五类统计由当次成功 results 动态计算；未查询或失败显示占位，不硬编码正常日数量。

## 核对记录与金额

使用原生按钮选择记录，列表包含全部结果。默认选首条 field_mismatch；没有冲突时优先首条非matched，否则第一条。按状态查找，不使用 O002 等编号硬编码。摘要包含状态、订单、录音或完整候选关系和原始理由摘要；候选始终不作为确认配对。

选中后在详情中保留候选集合、原始冲突、双方值、全部判断理由、原句、字段标签、时间和播放器。列表摘要最多两行，完整理由与转写不裁切。切换记录只使用同一次响应，不重新请求Pi；新日期/查询会清理旧选择。按钮和标签可由键盘操作；手机用户选择后会滚动并聚焦详情。

金额仍以整数分为内部数据，视图换算人民币元、两位小数。差异金额为两个有效安全整数分值的绝对差，再换算显示；不能从 AI 说明取值。原始理由仍逐字保留，因此其中整数金额可仍以分表示，页面不再为每条附加重复单位免责声明。

## 录音与转写

同一核对结果内，仅 recording_id、segment_index、start_ms、end_ms、text 五属性完全相同时合并为一份证据卡。所有字段标签和冲突专属引用参与合并，原始业务对象不变；不同录音/片段不误合并。多个录音候选分别保留，不凭编号选唯一最佳。

证据按钮等待 metadata，按 start_ms/1000 跳转并播放；timeupdate 达到 end_ms 后暂停。没有新增剪辑、ASR 或词级时间戳。当前音频为合成语音，字幕是服务估计的整句级边界，不代表物理词级精度；此限制保留在文档，不为每条证据重复附文。

音频失败显示警告，缺失录音不补造播放器或转写。切换记录、输入/查询变化、进入报告都会停止旧音频及待播回调；证据按钮与原生播放器的play事件均协调其他录音暂停，防止同时播放。

## AI 说明、安全 Markdown 与精简规则

AI 解释始终标识为“AI核对报告”，没有伪装成人工审定结果。全文业务解释保留，不额外调用模型摘要。采用固定 DOM 标签与 textContent，支持h1/h2/h3及0–3个标题前空格、CRLF/LF/CR换行、加粗、段落、ul/ol和安全引用；多列表格按原行列序转换成纵向字段卡片。不使用不可信innerHTML，不生成可执行HTML、图片、脚本或危险链接。

模型原 finalAnswer、工具结果和日志不修改。只有下面的独立完整段落/单个列表项会在 AI 视图中精确省略；混合了业务事实、异常、证据、候选、限制或依据的段落完整保留，绝不按 audit_day 等关键词粗暴删除。表格、原始 reasons 和 transcript 不经过此过滤。

- 业务判断以结构化工具结果为依据。候选关系保留待确认状态，不据此推定已匹配。
- 以上结论均来自 audit_day 结构化结果，未作额外推断。
- 窗口时间与转写时间均为整句范围（非词级精确时间）。

独立合法 Run ID 元说明行也不显示；若与业务事实混合则保留事实段。HTTP 响应中的 runId 始终保留。无法安全识别的元说明宁可保留，不猜测改写。

## 验收与限制

完整项目执行npm.cmd run typecheck、npm.cmd test、npm.cmd run validate:data。Stage 6早期前端基线为499项，主从工作台完成后为513/513（前端72项），包含动态金额、录音删除、日期切换、Markdown/XSS/去重/播放和记录/标签切换。公开仓库保留完整音频及自动化测试。

主从工作台浏览器检查使用已验证真实响应的明确标记离线回放，检查1440/1280/390px、键盘选择、金额、音频互斥和成功后失败清理，没有新增DeepSeek调用。既有真实10-15网页调用的[脱敏摘要](../evidence/submission/acceptance.md)可随材料阅读；历史10-16及UI回放记录保留开发归档，不把回放标为新在线验收。

本地演示范围不包含登录、数据库、多租户或订单写入。视频尚未录制，可参阅[演示大纲](07_demo_video_outline.md)。此项目未部署为公网 Web 服务。
